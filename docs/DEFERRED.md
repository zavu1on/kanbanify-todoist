# Отложенная работа

Реестр работы, которую осознанно не сделали, потому что она зависит от функционала, которого ещё нет. Не список идей и не бэклог фич — только то, что уже *должно* было бы существовать, но упирается в отсутствующую часть системы.

Ключевое поле каждой записи — <u>разблокируется, когда</u>. Запись без внятного триггера бесполезна: её никто не перечитает вовремя. Если триггера нет, значит это не отложенная работа, а идея — ей здесь не место.


## Как пользоваться

**Перед реализацией** — сверься с таблицей: не разблокирует ли текущая фича что-то из отложенного. Если да — сделай это в том же изменении или явно скажи пользователю, почему не делаешь.

**После реализации** — всё, что осознанно не сделал из-за отсутствующего функционала, занеси сюда строкой. Выполненные записи удаляй, а не помечай как сделанные: история живёт в git.

Оба шага прошиты в скиллы `feature-backend`, `feature-frontend` и `feature-fullstack`.


## Реестр

| Задача | Почему отложена | Разблокируется, когда | Откуда |
|---|---|---|---|
| Очистка кэша данных при выходе из аккаунта (`auth:logout`) | Кэша данных ещё не существует — нечего чистить | Появится любой кэш пользовательских данных в renderer или main | Реализация auth-роутинга |
| Счётчик подзадач «выполнено/всего» на **Карточке задачи** | Подзадачи — обычные задачи с `parentId`; без выделенного запроса по родителю или полного локального кэша задач подсчёт по одной странице пагинации даёт неверное число | Появится IPC-канал/use-case, считающий подзадачи по `parentId` независимо от текущей страницы пагинации | Реализация экрана «Задачи» |
| Контекстное меню **Карточки задачи** (дублирование, удаление) | Нет use-case/IPC-каналов для дублирования и удаления задачи (смена срока/приоритета уже доступна через `tasks:update` и **Детальное отображение задачи**) | Появятся каналы `tasks:duplicate`/`tasks:delete` в модуле `tasks` | Реализация экрана «Задачи» |
| Ручное упорядочивание карточек drag-and-drop на странице **Проекта** | Страница **Проекта** уже есть (переиспользует `TaskBoard`/`TaskListView`), но `useDragOnDropHandlers` поддерживает только перенос между колонками (смену Kanban-статуса) — нет use-case/IPC-канала, пишущего `childOrder` | Появится use-case/IPC-канал обновления ручного порядка задач в модуле `tasks` | Реализация проектов |
| Чекбокс «Создать ещё одну» и footer (дата создания, кнопка **Удалить**) в **Детальном отображении задачи** | Вне скоупа текущей фичи (только добавление/редактирование); удаление задачи упирается в отсутствующий канал `tasks:delete` (см. строку выше) | Появится явный запрос на эти элементы или канал `tasks:delete` | Реализация добавления/редактирования задачи |
| Подзадачи в **Детальном отображении задачи** | Вне скоупа текущей фичи; требует свой use-case для создания подзадачи с наследованием проекта и хлебной крошки для возврата к родителю | Появится отдельный запрос на управление подзадачами из детального отображения | Реализация добавления/редактирования задачи |
