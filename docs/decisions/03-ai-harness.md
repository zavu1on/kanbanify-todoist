# 03. AI-обвязка репозитория для разработки через Claude Code

**Дата:** 2026-08-03
**Автор:** mikhail
**Статус:** Принято
**Связанные решения:** [02-architecture.md](02-architecture.md)


## Контекст

Разработка ведётся преимущественно через AI-агента (Claude Code). Агент начинает каждую сессию с пустым контекстом: он не помнит, что архитектура бекенда нарезана по модулям, что ошибки не бросаются через IPC, что схему валидации нельзя дублировать на фронтенде и что `p1` — это `priority = 4`. Без обвязки эти правила приходится напоминать вручную в каждом запросе, а пропуск любого из них даёт код, который проходит компиляцию, но нарушает архитектуру — то есть требует ревью и переделки.

Конвенции уже описаны в двух руководствах ([`BACKEND_CODE_STYLE_GUIDE.md`](../BACKEND_CODE_STYLE_GUIDE.md), [`FRONTEND_CODE_STYLE_GUIDE.md`](../FRONTEND_CODE_STYLE_GUIDE.md)), но документ, лежащий в `docs/`, сам по себе в контекст не попадает — нужен механизм, который подтягивает нужное руководство к нужной задаче и задаёт порядок шагов.

Claude Code предлагает несколько типов сущностей с разными свойствами, и выбор между ними неочевиден:

- **скилл** — инструкция, загружаемая в текущий контекст по имени или по описанию задачи
- **агент (субагент)** — выполняется в изолированном контексте и возвращает отчёт, а не состояние
- **хук** — команда, которую исполняет сам Claude Code на событии, а не модель по своей воле
- **MCP-сервер** — внешний источник данных или инструментов
- **слэш-команда** — явная точка входа для пользователя

Ключевая развилка — как реализовывать фичу, затрагивающую оба процесса. Напрашивающийся вариант — субагент, объединяющий бекенд и фронтенд, — разбивается о природу субагента: общий IPC-контракт является состоянием, которое фронтенд-фаза должна унаследовать от бекенд-фазы, а субагент возвращает текстовый отчёт. Второй вопрос — что делать с шагами SDLC (формат, typecheck, тесты): они выполняются моделью по инструкции, то есть ровно настолько надёжно, насколько модель о них помнит в конце длинной сессии.


## Решение

Развернуть обвязку из скиллов, агента, хуков и MCP-сервера, разделив их по назначению; явными точками входа служат слэш-команды (`/feature`, `/feature-backend`, `/feature-frontend`, `/guide-review`). Вся обвязка хранится в `.claude/` этого репозитория, а не в домашней директории разработчика, — то есть версионируется вместе с кодом и одинакова у всех, кто клонирует проект. Полный актуальный перечень с таблицами — раздел «AI-инфраструктура» в [`CLAUDE.md`](../../CLAUDE.md); здесь — принцип разделения.

**1. Руководство — конвенции, скилл — процесс.** Скиллы не переписывают правила из руководств, а ссылаются на них и обязывают прочитать нужное перед работой. При расхождении прав документ в `docs/`, а скилл считается устаревшим. Это исключает второй источник правды, который неизбежно разошёлся бы с первым.

**2. Три скилла реализации** — `feature-backend`, `feature-frontend`, `feature-fullstack`. Каждый задаёт порядок: прочитать руководство и спецификацию → уточнить неясное → показать список файлов → реализовать → тесты → гейты → передать на ревью человеку. `feature-fullstack` — оркестратор: он проектирует IPC-контракт, затем прогоняет обе фазы **в одном контексте**, а не делегирует их субагентам.

**3. Один агент — `code-reviewer`**, read-only, сверяющий диф с обоими руководствами и спецификацией. Здесь изоляция контекста работает в плюс: агент не защищает код, который сам написал.

**4. Два хука** вместо доверия к дисциплине модели: `PostToolUse` форматирует каждый изменённый файл через Biome, `Stop` запускает `yarn typecheck` и `yarn test` перед завершением работы и при красном результате не даёт закончить, возвращая вывод модели на починку. Гейты пропускаются, если в `src/` нет изменений, и не срабатывают повторно при уже активном stop-хуке — чтобы непочиняемая ошибка не зациклила сессию.

**5. MCP-сервер `mantine`** — источник актуального API компонентной библиотеки, чтобы фронтенд-код не писался по памяти модели.

**6. Плагин `ponytail`** ([`DietrichGebert/ponytail`](https://github.com/DietrichGebert/ponytail), включён в [`.claude/settings.json`](../../.claude/settings.json)) — внешний набор скиллов, который заставляет агента выбирать минимальное работающее решение: не заводить абстракцию под один случай, не тащить зависимость ради нескольких строк, не писать код «на будущее». Это противовес естественному перекосу модели в сторону избыточных решений. При конфликте с руководствами по коду прав **руководство**: обязательные слои чистой архитектуры и публичные API слайсов — это принятая цена за границы модулей, а не боилерплейт, который плагин вправе срезать.

**Реализация фичи на практике.** Например, страница **Задачи** — списочный режим с загрузкой задач из Todoist. Она пересекает границу процессов, поэтому запускается фуллстек-скилл:

```
/feature страница Задачи: списочный режим с пагинацией, раздел «Задачи» в SPECIFICATION.md
```

Дальше агент проходит по шагам скилла:

1. **Проектирует контракт** и показывает его до написания кода: канал `tasks:list`, аргумент с курсором, ответ `{ ok: true; tasks: Task[]; nextCursor: string | null } | { ok: false; error: { type; message } }`. Здесь же всплывает, что пагинация — часть контракта, а не деталь UI, и что <u>deadline</u> использовать нельзя
2. **Бекенд-фаза** — читает [`BACKEND_CODE_STYLE_GUIDE.md`](../BACKEND_CODE_STYLE_GUIDE.md), сверяется со скиллом `todoist-sdk` по сигнатурам SDK и заводит модуль `tasks` по рецепту: сущность → порт → use-case → gateway → IPC-контроллер → barrel → сборка в `src/main/index.ts` → метод в `window.api`
3. **Фронтенд-фаза** — читает [`FRONTEND_CODE_STYLE_GUIDE.md`](../FRONTEND_CODE_STYLE_GUIDE.md), запрашивает пропсы компонентов у MCP-сервера `mantine`, заводит слайс страницы с `model/` поверх `window.api.tasks.list` и импортирует тип результата из `@/main/tasks`
4. **Гейты** — `yarn format` уже отработал хуком на каждом файле; `yarn typecheck` и `yarn test` запускаются явно и повторно проверяются stop-хуком
5. **Ревью** — `/guide-review` запускает `code-reviewer` по дифу, затем работа передаётся человеку; коммит оформляется скиллом `git-commit` только по явной просьбе

Для правки, не выходящей за один процесс, скилл вызывается напрямую: `/feature-frontend` или `/feature-backend`.


## Последствия

- Конвенции применяются без ручного напоминания в каждом запросе: скилл сам подтягивает нужное руководство, а руководства содержат пошаговые рецепты и списки запретов — агент реже изобретает собственную структуру.
- Разделение «руководство — конвенции, скилл — процесс» не даёт правилам раздвоиться, но добавляет обязательное чтение документа в начало каждой сессии реализации: это расход контекста и времени, который окупается только пока руководства остаются точными.
- Отказ от фуллстек-субагента сохраняет IPC-контракт в одном контексте, но означает, что длинная фича целиком расходует основной контекст сессии — на больших задачах вероятна компактификация контекста в процессе.
- Хуки переносят шаги SDLC из области дисциплины модели в область исполнения самим Claude Code: пропустить `yarn typecheck` или тесты нельзя, даже если модель о них забыла. Плата — задержка на завершении каждой сессии, где менялся `src/`, и жёсткая привязка к тому, что оба скрипта остаются быстрыми; если прогон тестов вырастет до минут, гейт придётся сужать до изменённых файлов.
- Stop-хук способен заблокировать завершение сессии при ошибке, которую агент не может починить (например, сломанное окружение). Защита от зацикливания есть — повторно хук не блокирует, — но при её срабатывании красный гейт молча пропускается, поэтому вывод проверок всё равно нужно читать глазами.
- Read-only агент ревью даёт независимую сверку с руководствами до человеческого ревью, но это ещё одна сущность, которую нужно поддерживать в согласии с руководствами: устаревший чек-лист ревьюера будет уверенно сообщать о несуществующих нарушениях.
- Обвязка сама становится частью кодовой базы: скиллы, агент, хуки и таблицы в `CLAUDE.md` требуют обновления в том же коммите, что и изменение процесса, — иначе описание разойдётся с поведением. Правило актуализации зафиксировано в [`CLAUDE.md`](../../CLAUDE.md).
- `ponytail` — первая часть обвязки из внешнего источника: она обновляется вне репозитория и может менять поведение агента без коммита в проект. Взамен снижается объём кода, который приходится вычищать на ревью. Конфликт с руководствами разрешается в пользу руководств, но разрешать его придётся вручную — автоматической проверки на то, что минимизация не срезала обязательный слой, нет.
- Обвязка привязана к Claude Code: скиллы, агенты и хуки не переносятся в другой AI-инструмент без переписывания, хотя сами руководства в `docs/` остаются инструментонезависимыми.
