# Техническое задание

**Kanbanify Todoist** — desktop-приложение (Electron), UI-клиент для Todoist, добавляющий **Kanban-статусы** (Kanban Status) задачам через встроенные теги Todoist.


## Ограничения тарифа

Приложение ориентировано **только** на community-функционал Todoist — тот, что доступен на бесплатном тарифе (Beginner). Функции платных тарифов не используются даже при их наличии у пользователя.

Из этого следуют ограничения, на которые опирается вся остальная спецификация:

- Поле <u>крайний срок</u> (`deadline`) — функция тарифа Pro, поэтому в приложении **не используется вовсе**. Роль дедлайна во всех экранах играет поле <u>срок</u> (`due`) — единственное поле даты, доступное на бесплатном тарифе
- <u>Длительность</u> задачи (`duration`) — функция тарифа Pro, не используется
- История активности хранится Todoist только за последнюю неделю, поэтому она не может быть источником данных для дашборда
- Лимиты в 5 проектов и 3 сохранённых фильтра заданы самим Todoist — приложение их не обходит и не отображает


## Доменная модель

**Задача** (Task) — сущность Todoist. Значимые для приложения поля: <u>название</u>, <u>описание</u>, <u>срок</u>, <u>приоритет</u>, <u>лейблы</u>, <u>проект</u>, <u>родительская задача</u>, <u>признак выполнения</u>.

**Проект** (Project) — сущность Todoist, контейнер задач. Задача без явного проекта попадает во **Входящие** (Inbox).

**Лейбл** (Label) — тег Todoist, привязанный к задаче.

**Kanban-статус** (Kanban Status) — статус задачи в kanban-процессе. Хранится не отдельной сущностью, а **зарезервированным Лейблом** на задаче, поскольку community-версия API Todoist не предоставляет нативного поля статуса. Возможные значения: *без статуса* (ни одного зарезервированного лейбла на задаче), `todo`, `in-progress`, `completed`.

Kanban-статус `completed` **не равен** выполненной задаче в Todoist: задача с лейблом `completed` остаётся активной (`checked = false`), пока пользователь не завершит её чекбоксом. Это две независимые оси состояния, и приложение нигде их не синхронизирует автоматически.

Если на задаче почему-либо оказалось несколько зарезервированных лейблов, приложение считает актуальным самый *правый* по порядку kanban-колонок: сначала `completed`, затем `in-progress`, затем `todo`. У такой карточки показывается предупреждающий значок.

**Срок** (Due Date) — дата выполнения задачи, опционально со временем. Задача считается **просроченной**, если её срок раньше текущего дня, а при заданном времени — раньше текущего момента. Это соответствует поведению фильтра `overdue` в Todoist, из-за чего задача со сроком *сегодня 10:00* после 10 часов одновременно попадает и под `today`, и под `overdue`. Везде, где приложение показывает просроченные и сегодняшние задачи рядом, такая задача относится к просроченным и в сегодняшних **не** дублируется.

**Приоритет** (Priority) — четыре уровня, обозначаемые как в интерфейсе Todoist: `p1` — наивысший, `p4` — обычный (значение по умолчанию). В API Todoist нумерация обратная (`priority = 4` соответствует `p1`), поэтому во всех формулировках спецификации имеется в виду именно интерфейсное обозначение.


## Авторизация

Авторизация выполняется по личному **Токену доступа** (Access Token) Todoist, без OAuth-флоу.

### Обоснование

OAuth-флоу требует зарегистрированного приложения и обмена кода авторизации на токен с использованием `client_secret`, который в устанавливаемом на компьютер пользователя приложении хранить негде — он перестаёт быть секретом. Извлечь готовый токен из redirect URL тоже невозможно: редирект возвращает одноразовый код авторизации, а не токен.

При этом Todoist выдаёт пользователю бессрочный личный токен прямо в настройках, и он полностью покрывает сценарий персонального клиента. Поэтому приложение использует именно его.

### Экран входа

Показывается, если сохранённого токена нет или он перестал быть валидным. Содержит:

- Поле ввода <u>токен доступа</u> — по умолчанию содержимое скрыто (как пароль), с кнопкой-глазом для показа
- Пошаговую инструкцию получения токена: *Todoist → аватар в левом верхнем углу → Settings → Integrations → Developer → Copy API token*
- Кнопку **Войти**, неактивную при пустом поле
- Область для сообщения об ошибке

Кнопка **Войти** запускает проверку токена запросом данных пользователя. Возможные исходы:

- Успех — токен сохраняется, пользователь попадает на **Дашборд**
- Ошибка аутентификации (HTTP 401/403) — сообщение «Токен недействителен. Проверьте, что скопирован актуальный токен из настроек Todoist», токен не сохраняется
- Сетевая ошибка — сообщение «Не удалось связаться с Todoist. Проверьте подключение к интернету» и кнопка **Повторить**
- Прочая ошибка API — текст ошибки и её HTTP-код

### Хранение токена

Токен сохраняется персистентно и переживает перезапуск приложения:

- Шифрование выполняется штатным механизмом Electron `safeStorage`, использующим ключ из хранилища секретов ОС (Windows DPAPI, macOS Keychain, Linux libsecret)
- Шифротекст записывается в файл в каталоге `app.getPath('userData')`
- Токен в открытом виде существует **только** в main-процессе; renderer-процесс токена не получает и обращается к Todoist через IPC
- Если шифрование в системе недоступно (`safeStorage.isEncryptionAvailable() === false`, типично для Linux без keyring), приложение показывает предупреждение о том, что токен будет храниться в открытом виде, и просит явного подтверждения. При отказе токен хранится только в памяти сессии

Токен нигде не логируется и не попадает в сообщения об ошибках.

### Сессия

При старте приложение читает сохранённый токен и проверяет его запросом данных пользователя. При успехе открывается **Дашборд**, при ошибке аутентификации — экран входа с сообщением «Срок действия токена истёк или он был отозван. Введите новый токен».

Если ошибка аутентификации приходит в ответ на любой запрос во время работы, приложение прекращает фоновые запросы, очищает кэш данных и возвращает пользователя на экран входа с тем же сообщением.

**Выход** из карточки пользователя в сайдбаре удаляет файл с токеном, очищает кэш данных и открывает экран входа. Действие требует подтверждения в диалоге, поскольку токен придётся вводить заново.


## Сайдбар

Слева расположен сайдбар, с помощью которого происходит навигация по вкладкам:

- `+` (Создание новой задачи)
- **Поиск** (Search)
- **Дашборд** (Dashboard)
- **Задачи** (Tasks)
- **Сегодня** (Today)
- **Календарь** (Calendar)

У пунктов **Сегодня** и **Задачи** справа отображается счётчик активных задач; у **Сегодня** он включает просроченные.

Далее идёт отсекающая линия — разделитель, после которого отображаются **Проекты** пользователя в порядке, заданном в Todoist, с цветовой меткой проекта и счётчиком активных задач. Вложенные проекты отображаются с отступом, родительский проект сворачивается. Выбор проекта открывает страницу проекта — она полностью повторяет страницу **Задачи** (оба режима отображения, те же действия), но ограничена задачами выбранного проекта.

Внизу сайдбара отображается карточка пользователя с аватаром и именем, ниже — версия приложения. При нажатии на карточку появляется всплывающее меню над карточкой с пунктом **Выйти**.

Сайдбар сворачивается в узкую полосу с иконками (бургер-меню); состояние сворачивания сохраняется между запусками.


## Управление проектами

Над списком **Проектов** в сайдбаре — кнопка `+`, открывающая модальное окно добавления проекта. У каждого проекта в списке — кнопка-троеточие, открывающая меню с пунктами **Редактировать**, **Архивировать** и **Удалить**.

Поля формы добавления/редактирования: <u>название</u> (обязательное, до 120 символов), <u>описание</u>, <u>цвет</u> — интерфейс идентичен добавлению задачи в оригинальном Todoist. <u>Родительский проект</u> редактируется только при создании — Todoist API не позволяет сменить родителя у уже существующего проекта, поэтому в форме редактирования это поле показывается нередактируемым (см. [`DEFERRED.md`](DEFERRED.md)). <u>Описание</u> проекта дополнительно отображается на странице его задач, под названием.

**Архивация** и **Удаление** требуют двойного подтверждения: первый диалог перечисляет последствия действия, второй — финальное предупреждение с кнопкой самого действия. После успешной архивации показывается сообщение, что разархивировать проект можно только в оригинальном приложении Todoist — этот клиент такой функции не предоставляет. Оба действия недоступны для проекта **Входящие** (Todoist не позволяет архивировать или удалять его).


## Добавление задачи

При нажатии на `+` в сайдбаре открывается модальное окно создания задачи — то же самое **Детальное отображение задачи**, что используется для просмотра и редактирования (см. раздел «Задачи»), в режиме создания.

Отличия режима создания от режима редактирования:

- Заголовок окна — «Новая задача», кнопка подтверждения — **Добавить**
- Поля предзаполняются из контекста вызова: со страницы проекта — <u>проект</u>; из kanban-колонки — соответствующий <u>Kanban-статус</u>; из ячейки календаря или страницы **Сегодня** — <u>срок</u>; при добавлении подзадачи — <u>родительская задача</u>. Из сайдбара контекста нет: <u>проект</u> = **Входящие**, остальные поля пусты
- Обязательно только <u>название</u>; кнопка **Добавить** неактивна, пока оно пусто
- Подзадачи в режиме создания добавить нельзя — сначала должна быть создана сама задача. Блок подзадач показывается неактивным с пояснением
- Доступен чекбокс **Создать ещё одну** — после сохранения окно не закрывается, поля очищаются, а <u>проект</u>, <u>срок</u> и <u>Kanban-статус</u> сохраняются для следующей задачи

Поле <u>название</u> поддерживает быстрый ввод в синтаксисе Todoist: `#проект`, `@лейбл`, `p1`–`p4`, дата естественным языком («завтра в 12:00»). Распознанные фрагменты подсвечиваются в поле ввода и одновременно проставляются в соответствующие поля формы, из названия при сохранении они вырезаются. Если пользователь правит поле формы вручную, разбор соответствующего фрагмента отключается до следующего изменения названия.

Сохранение выполняется оптимистично: окно закрывается сразу (а при включённом чекбоксе **Создать ещё одну** — очищается), задача появляется в списке в состоянии *сохраняется*. При ошибке API карточка помечается ошибкой, а окно открывается заново с введёнными данными — они не теряются.

Закрытие окна с несохранёнными изменениями (`Esc` или клик вне окна) требует подтверждения.


## Поиск

Модальное окно поиска открывается из сайдбара и по горячей клавише. Поиск гибридный: свободный текст плюс уточняющие фильтры-чипы, которые вместе собираются в один запрос на языке фильтров Todoist.

### Ввод

Верхняя часть окна — поле свободного текста и строка добавленных чипов.

Введённый текст превращается в условие `search: <текст>`. Чипы добавляются кнопкой рядом с полем ввода или вводом префикса прямо в поле (`#` — проект, `@` — лейбл, `p1`–`p4` — приоритет) с автодополнением по загруженным проектам и лейблам. Ввод `@` с именем зарезервированного лейбла даёт чип **Kanban-статуса**, а не чип лейбла.

Доступные типы чипов:

- **Проект** — один или несколько, объединяются через `|`
- **Лейбл** — один или несколько, объединяются через `|`
- **Kanban-статус** — включая вариант *без статуса*, который разворачивается в отрицание всех зарезервированных лейблов
- **Приоритет** — `p1`–`p4`
- **Срок** — *сегодня*, *просрочено*, *ближайшие 7 дней*, *без срока*, *есть срок*
- **Тип задачи** — *только родительские* (`!subtask`) или *только подзадачи* (`subtask`)
- **Включать выполненные** — чип-переключатель, добавляющий в выдачу секцию выполненных задач

Чипы разных типов объединяются через `&`, одного типа — через `|` внутри скобок. Итоговый запрос всегда виден под полем ввода в свёрнутой строке; нажатие на неё переключает окно в **режим сырого запроса**, где строка редактируется вручную на языке фильтров Todoist целиком. Возврат из сырого режима к чипам возможен, только если запрос не правился вручную; иначе приложение предупреждает, что чипы будут собраны заново из того, что удалось распознать.

### Выдача

Результаты сгруппированы по секциям, каждая сворачивается:

- **Проекты** — совпадения по названию проекта
- **Лейблы** — совпадения по названию лейбла
- **Задачи** — активные задачи, соответствующие собранному запросу, в виде **Карточек задачи**
- **Выполненные** — показывается, только если включён соответствующий чип; ищется отдельным запросом к выполненным задачам, поддерживает только текстовую часть запроса, о чём под секцией выводится пояснение

Секции **Проекты** и **Лейблы** заполняются только текстовой частью запроса и скрываются, если она пуста.

Запрос отправляется с задержкой в 300 мс после последнего изменения ввода; предыдущий незавершённый запрос отменяется. Секция задач поддерживает догрузку по кнопке **Загрузить ещё**, поскольку упирается в тот же лимит в 200 элементов.

Навигация по результатам возможна с клавиатуры: стрелки перемещают выделение, `Esc` закрывает окно, `Enter` открывает выделенный результат — для задачи это **Детальное отображение задачи**, для проекта — его страница, для лейбла — страница **Задачи** с фильтром по этому лейблу.

Пустая выдача показывает подсказку с примерами запросов. Синтаксическая ошибка в сыром режиме показывает сообщение от API с указанием, что запрос не распознан.

Последние 10 запросов сохраняются и предлагаются при открытии окна с пустым полем.


## Дашборд

Первая страница, которая встречает пользователя при открытии приложения. Дашборд поделён на карточки с метриками.

Данные для карточек берутся из трёх источников: полного списка активных задач (обходится постранично и кэшируется на время сессии), счётчиков по фильтрам (считает сервер Todoist) и статистики продуктивности. Кэш активных задач инвалидируется при любом изменении задачи из приложения и по кнопке **Обновить** в шапке дашборда.

### Общая информация по задачам

Три числа:

- <u>Активных задач</u> — количество невыполненных задач, из полного списка активных задач
- <u>Выполнено за всё время</u> — накопительный счётчик Todoist. Рядом значок с пояснением: счётчик ведёт сам Todoist, каждое завершение повторяющейся задачи учитывается отдельно, а удалённые задачи из него не вычитаются
- <u>Выполнено сегодня</u> — счётчик выполненного за текущий день

### Сроки

Четыре счётчика, каждый по клику открывает соответствующий список задач:

- <u>Просрочено</u> — фильтр `overdue`
- <u>Сегодня</u> — фильтр `today & !overdue`, чтобы задача с прошедшим временем не попала в оба счётчика сразу
- <u>Ближайшие 7 дней</u> — фильтр `next 7 days & !overdue`; включает сегодняшние задачи, то есть перекрывается с предыдущим счётчиком
- <u>Без срока</u> — фильтр `no date`

Ниже — таблица задач, у которых срок наступает менее чем через 2 недели, отсортированная по возрастанию срока. Каждая строка — **Карточка задачи**, но вместо даты в ней отображается актуальное количество дней до срока («сегодня», «завтра», «через N дней»). Просроченные задачи в таблицу не попадают — для них есть отдельный счётчик. Таблица показывает первые 10 задач, остальные раскрываются кнопкой **Показать все**.

### Информация по kanban-доске

Распределение активных задач по **Kanban-статусам**: *без статуса*, `todo`, `in-progress`, `completed`. Отображается числами и горизонтальной полосой долей.

Метрика считается локально по кэшу активных задач, поскольку статус — это лейбл на задаче. Выполненные задачи Todoist в распределение не входят.

Клик по сегменту открывает страницу **Задачи** в kanban-режиме с подсветкой соответствующей колонки.

### Динамика

График выполненных задач с переключателем масштаба:

- **По дням** — столбцы за последние ~7 дней, поверх — горизонтальная линия дневной цели пользователя
- **По неделям** — столбцы за последние ~4 недели, поверх — линия недельной цели

Источник — статистика продуктивности Todoist (один запрос, доступен на бесплатном тарифе). Глубина ряда определяется тем, что возвращает API; приложение не достраивает и не экстраполирует отсутствующие точки, а показывает ровно полученные.

Рядом с графиком — текущий дневной стрик (количество дней подряд с достигнутой целью) и его рекордное значение.

График показывает только *выполнение*; создание задач в динамику не выносится, так как достоверных данных о создании на бесплатном тарифе нет.


## Задачи

На данной странице отображаются все невыполненные задачи пользователя — из всех проектов, включая **Входящие**. Так как Todoist имеет встроенную пагинацию с максимальным количеством элементов списка 200, то внизу страницы должна быть кнопка **Загрузить ещё**, подгружающая следующую страницу по курсору. Кнопка скрывается, когда API сообщает, что страница последняя.

Страница имеет два вида отображения, выбор сохраняется между запусками:

1. **Списочное** — плоский список **Карточек задачи**
2. **Kanban** — 4 колонки по **Kanban-статусам**: *без статуса*, `todo`, `in-progress`, `completed`

В шапке страницы — переключатель вида, сортировка (по сроку, по приоритету, по дате создания, вручную) и быстрый фильтр по проекту и лейблу.

### Kanban-режим

У каждой колонки есть заголовок со счётчиком задач и кнопка `+`, создающая задачу сразу с соответствующим **Kanban-статусом**.

Перетаскивание карточки между колонками меняет **Kanban-статус**: приложение убирает у задачи прежний зарезервированный лейбл и добавляет новый, сохраняя все прочие лейблы. Перетаскивание в колонку *без статуса* убирает зарезервированный лейбл и не добавляет ничего. Изменение применяется оптимистично; при ошибке API карточка возвращается в исходную колонку с сообщением об ошибке.

Перетаскивание внутри колонки меняет ручной порядок задач. Ручной порядок Todoist определён только в пределах одного проекта, поэтому в смешанном списке (страница **Задачи**, где задачи из разных проектов) сортировка вручную недоступна — переключатель сортировки в этом случае показывает её неактивной с пояснением. На странице проекта сортировка вручную доступна.

Колонки прокручиваются независимо; догрузка по кнопке **Загрузить ещё** относится ко всей странице сразу, а не к отдельной колонке.

### Карточка задачи

**Карточка задачи** (элемент списка) отображает: <u>название</u>, <u>срок</u> (с подсветкой красным, если задача просрочена, и выделением, если срок сегодня), <u>Kanban-статус</u> (если есть), <u>приоритет</u> (цветовой меткой, если он выше обычного), <u>лейблы</u> кроме зарезервированных, <u>проект</u> (если задача не во **Входящих**), количество подзадач в формате «выполнено/всего».

Слева у карточки чекбокс, завершающий задачу. Запрос на завершение уходит сразу оптимистично — задача исчезает из списка немедленно; при ошибке API изменение откатывается.

Правый клик по карточке открывает контекстное меню: смена **Kanban-статуса**, смена <u>срока</u> (сегодня, завтра, следующая неделя, убрать срок, произвольная дата), смена <u>приоритета</u>, дублирование, удаление. Удаление требует подтверждения и не отменяется.

Клик по карточке открывает **Детальное отображение задачи**.

### Детальное отображение задачи

Модальное окно, аналогичное окну задачи в Todoist, но только с полями, доступными на бесплатном тарифе. Служит одновременно для просмотра, редактирования и создания задачи.

Поля: <u>название</u>, <u>описание</u> (многострочное, с поддержкой Markdown), <u>срок</u> (выбор даты в календаре, опционально время, ввод естественным языком, кнопка очистки), <u>приоритет</u> (`p1`–`p4`), <u>Kanban-статус</u> (выпадающий список из четырёх значений), <u>лейблы</u> (мультивыбор с поиском и созданием нового), <u>проект</u> (выпадающий список), <u>подзадачи</u>.

Блок подзадач показывает их **Карточками задачи** и позволяет добавить новую строкой ввода внизу блока; созданная подзадача наследует <u>проект</u> родителя. Подзадача открывается в том же окне с хлебной крошкой для возврата к родителю.

Заголовок окна содержит хлебную крошку «Проект / Родительская задача». В подвале — дата создания задачи и кнопка **Удалить** с подтверждением.

Редактирование сохраняется по потере фокуса поля; окно не имеет кнопки **Сохранить** в режиме редактирования. Индикатор сохранения показывается рядом с заголовком.

Поле <u>лейблы</u> не предлагает в автодополнении зарезервированные лейблы `todo`, `in-progress` и `completed` — они управляются полем <u>Kanban-статус</u>. Если пользователь всё же добавляет такой лейбл вручную, показывается предупреждение о том, что лейбл зарезервирован под **Kanban-статус** и будет интерпретирован приложением как статус задачи; после подтверждения лейбл добавляется и поле <u>Kanban-статус</u> синхронно обновляется.


## Сегодня

Страница повторяет **Задачи** — те же два вида отображения, те же карточки и действия — но ограничена задачами, срок которых наступил: фильтр `today | overdue`.

Списочный вид разделён на две секции:

1. **Просрочено** — со счётчиком и кнопкой **Перенести всё на сегодня**, массово обновляющей срок у задач секции. Действие требует подтверждения и в течение 5 секунд отменяется уведомлением, возвращающим каждой задаче её прежний срок
2. **Сегодня** — с указанием текущей даты в заголовке; задачи с сегодняшним сроком и уже прошедшим временем относятся к первой секции и здесь не показываются

В kanban-режиме просроченные задачи распределены по тем же четырём колонкам вместе с сегодняшними и выделены красной меткой срока.

Кнопка `+` на этой странице создаёт задачу со сроком *сегодня*.

Если задач нет, показывается состояние «На сегодня всё» с количеством задач, выполненных за день.


## Календарь

На данной странице отображаются все невыполненные задачи, у которых выставлен <u>срок</u> (аналогично странице Upcoming в Todoist). Задачи без срока на странице не показываются; их количество выведено ссылкой в шапке, ведущей на страницу **Задачи** с фильтром *без срока*.

Так как Todoist имеет встроенную пагинацию с максимальным количеством элементов списка 200, страница подгружает задачи автоматически: списочный вид — при прокрутке к концу списка, календарный — при переходе к месяцу, для которого данные ещё не загружены. Пока идёт загрузка, список и ячейки календаря показывают состояние загрузки, а не пустоту.

Страница имеет два вида отображения, выбор сохраняется между запусками.

### Списочное отображение

Задачи сгруппированы по дням, начиная с текущего, каждая группа озаглавлена датой и днём недели. Просроченные задачи вынесены отдельной секцией наверх — с кнопкой **Перенести всё на сегодня**, как на странице **Сегодня**.

В заголовке каждой группы есть кнопка `+`, создающая задачу со сроком на эту дату.

Дни без задач пропускаются.

### Календарное отображение

Сетка календаря на месяц с кнопками навигации *предыдущий месяц*, *следующий месяц*, *сегодня*. Первый день недели берётся из настроек пользователя Todoist.

В ячейке дня — компактные карточки задач (<u>название</u>, цветовая метка <u>приоритета</u>, метка <u>Kanban-статуса</u>, время, если у срока задано время). Задачи в ячейке отсортированы: сначала со временем по возрастанию, затем без времени. Если задачи не помещаются, показывается «ещё N» — клик раскрывает список задач дня во всплывающем окне.

Текущий день выделен. Ячейки прошедших дней с невыполненными задачами подсвечены как просроченные.

Наведение на ячейку показывает кнопку `+`, создающую задачу со сроком на эту дату; двойной клик по пустому месту ячейки делает то же самое.

Перетаскивание карточки в другую ячейку меняет <u>срок</u> задачи на дату этой ячейки; время в сроке, если оно было задано, сохраняется. Изменение применяется оптимистично, при ошибке карточка возвращается на прежнее место с сообщением об ошибке.

Клик по карточке открывает **Детальное отображение задачи**.

Почасовая сетка внутри дня не строится: длительность задачи — функция платного тарифа и приложением не используется, поэтому время у задачи отображается только меткой на карточке.
